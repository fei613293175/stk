# 数据库迁移执行顺序

按 `V1.0.0 → V1.1.0 → V1.2.0 → V1.3.0 → V1.4.0` 只向前执行。迁移由 Discuz 插件安装/升级入口调用，不允许管理员手工复制不完整 SQL。

## 强制规则

- `pre_` 由 Discuz 当前表前缀替换；禁止写死线上前缀。
- 每个迁移版本必须写入插件自身版本状态，成功提交后才升级版本号。
- DDL 前执行数据库兼容性和备份检查；大表索引在维护窗口执行。
- 不使用数据库外键，引用完整性由事务、服务层和合同测试保证，以避免破坏 Discuz 兼容部署。
- 联系方式、手机号、短信验证码可查看密文均使用服务端主密钥加密；Hash 使用带服务器 Pepper 的 HMAC。
- 注册事务必须原子完成：Discuz UID、手机号绑定、inactive 会员记录、`commission`/`task` 两个 `0.00 CNY` 账户；任一步失败全部回滚。
- 卸载默认保留业务数据；只有超级管理员二次确认并生成备份后才允许删除表。
