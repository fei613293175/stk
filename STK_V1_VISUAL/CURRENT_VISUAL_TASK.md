# 当前任务：V1.0.0 Beta 2 详细视觉完善

## 目标

在保留当前可运行 `1.0.0-beta.1` 功能、后端连接和构建链路的前提下，根据 `ui-reference/detailed/V1.0.0/` 中 67 张批准效果图，完善 V1.0.0 的页面结构和全部 UI 状态，并交付可覆盖安装的 `1.0.0-beta.2` APK。

## 权威顺序

1. 功能与数据：当前仓库的 `CURRENT_TASK.md`、API/后端合同和已经工作的代码；
2. 颜色、字号、圆角、边距、组件、页面布局：本包效果图和 `docs/UI_DESIGN_SYSTEM.md`；
3. 效果图中的示例文字、手机号、金额、日期、头像和项目内容：仅为展示数据，不得据此新增功能。

## 不允许做

- 不重置仓库；
- 不替换已经能工作的 Gradle、AGP、Kotlin、JDK、SDK 或签名；
- 不重写 Discuz 插件和认证架构，除非现有 UI 状态确实无法表达合同结果；
- 不把 67 张图变成 67 个独立 Screen；
- 不新增 API 37、模拟器全量遍历、像素级 CI 阻断或 67 图自动截图比较；
- 不处理 V1.1.0 及以后功能；
- 不因视觉完善延迟第一个 beta.2 APK 超过同类故障止损时间。

## 实施方法

### 第 0 步：现状审计（最多 15 分钟）

- 列出当前已经实现的页面、组件和 UI 状态；
- 将 67 个 State ID 标记为：`已符合 / 需要调整 / 尚未实现 / 不适用说明`；
- 不先重构工程，不先写新规则。

### 第 1 步：先锁公共设计系统

先完成 `B00`：颜色、字体、行高、间距、圆角、顶部导航、底部导航、按钮、输入框、卡片、Dialog、Snackbar、加载、错误和空状态。

业务页面不得继续硬编码新的颜色、sp、dp、圆角。相同组件只保留一个实现。

### 第 2 步：按批次修改

严格按 `VISUAL_BATCHES.csv` 的 B01～B05 执行。每批：

1. 读取该批全部效果图和状态说明；
2. 复用同一 Screen + UI state + 公共组件表达各状态；
3. 修正布局、字号、圆角、边距、高度、颜色和反馈样式；
4. 保持真实功能和接口不变；
5. 运行 `scripts/fast-check.sh` 和 `assembleDebug`；
6. 更新 `VISUAL_IMPLEMENTATION_STATUS.csv`；
7. 进入下一批，不等待模拟器或全量视觉 CI。

### 第 3 步：最终交付

- `versionName = 1.0.0-beta.2`；
- `versionCode = 10002`；
- 使用与 beta.1 相同的 Beta 签名，验证覆盖安装；
- 交付 APK、SHA-256、Commit、功能未变说明、67 状态完成表、Owner 测试步骤；
- 只人工抽查每个页面至少 1 个代表状态，不要求 67 张全部自动截图。

## 完成标准

- 67 个 State ID 均有明确实现状态；
- 所有 V1.0.0 页面使用统一设计 Token；
- 登录、注册、安全验证码、风控、协议、系统错误、首页空态、我的和退出状态均可由现有 ViewModel/Fake 状态触发；
- 不存在空白页、按钮无响应或每页自定义一套视觉参数；
- beta.2 可覆盖安装 beta.1；
- 视觉修改未破坏现有登录、注册、退出和三导航功能。
