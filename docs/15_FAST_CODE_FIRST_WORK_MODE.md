# 15 流畅快速、代码优先的工作模式

本项目不采用重型治理循环。规则只用于防止范围、UI、交付和安全漂移，不允许把开发时间消耗在重复证明规则。

1. 每版开始只做一次预检：当前版本、效果图批准状态、分支、依赖、域名 Owner Action。
2. 立即按纵向 Feature 编码：数据库/接口/Android/后台/测试一起推进。
3. 开发中只运行受影响测试；版本关闭前才跑全量模拟器、视觉和 Release 验收。
4. 同一失败在输入未变化时不重复运行；先定位根因并修改。
5. 文档已有明确答案时不重新讨论架构、配色、字号、圆角、页面列表或版本划分。
6. 小问题直接修复；只有改变固定技术、数据兼容、安全或商业范围时才写 ADR。
7. 外部 DNS、短信审核或服务器权限未到位时，使用正式 Adapter/Fake 和 Owner Action 继续其他代码；不得返回永久假成功。
8. 连续两个工作循环没有代码、测试或运行结果时，必须停止泛化分析，列出单一阻塞并处理。
9. 每版只生成一次最终计划/完成/测试/交付文档，不重复生成内容相同报告。
10. 真实产出优先级：可运行代码 → 自动测试 → 必需合同更新 → 必需说明。
