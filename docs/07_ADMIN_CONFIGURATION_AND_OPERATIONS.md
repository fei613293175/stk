# 07 后台功能、配置、查询与运营规则

## 1. 后台交付原则

后台不是只有数据列表。每个可运营领域必须按适用性提供配置、筛选、详情、操作、批量、审计、诊断和错误反馈。角色采用最小权限；超级管理员可授权短信审计员、项目审核员、用户运营、会员运营、发布管理员和只读财务查看员。

## 3. 配置总表

配置明细位于 `contracts/config-inventory.csv`，共 **122 项**。每项都有后台入口、类型、默认值、校验、敏感性、运行时行为和版本。关键约束：

- `auth.force_login=true`；`captcha.enabled=true`；Refresh Token 轮换必须开启。
- `external.internal_webview_enabled=false`。
- `member.operation_enabled=false`、`wallet.operation_enabled=false`、`props.operation_enabled=false` 在五版本内不得开启。
- Release 记录必须包含 APK URL、SHA-256、versionCode、versionName、最低支持版本和更新类型。
- Secret 配置只保存加密密文，后台显示脱敏值；变更记录不包含明文。

## 4. V1.0 管理员交付

V1.0.0 必须交付：

- 后台地址 `https://stk-admin.zz-yihao.com/`；
- 现有管理员账号 `admin`；密码由项目所有者提供并仅保存在本机 `ADMIN_ACCESS_HANDOFF.local.md`；
- 本机文件 `ADMIN_ACCESS_HANDOFF.local.md`，禁止进入 Git、CI Artifact、日志或聊天；
- 首次登录后建议立即修改已提供密码并开启可用的二次验证；
- 登录后能访问 `stk_auth` 和当前版本 `stk_project` 菜单；
- 后台账号、权限、登录时间和交付人写入本机交付记录，但不保存明文密码。

## 5. 配置发布与回滚

普通文案/开关可热加载；Token TTL、密码规则、上传限制等变更在保存前校验；applicationId、签名和数据主键规则属于不可热变更。重要配置保存时形成前后摘要并可回滚到上一批准版本，Secret 只允许重新输入，不允许从历史恢复明文。
