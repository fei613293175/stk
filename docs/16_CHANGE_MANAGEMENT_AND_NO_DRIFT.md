# 16 变更管理与防漂移

固定事实改变时，先提交变更记录，再同步所有权威合同和受影响版本。禁止只改聊天、效果图、某个页面或某个接口。

## 需要正式变更的事项

- applicationId、签名、技术栈、主域名、仓库、版本划分；
- 登录/注册方式、注册是否发短信、安全验证码规则；
- 支付、会员、账户、道具、实名认证等商业范围；
- UI Token、公共组件和已批准效果图；
- 数据表兼容、API 字段删除或状态机变化。

## UI 变更

Token 变化先更新 `ui-design-tokens.yaml` 和 DS 规范板，再重新生成所有受影响效果图并审批。单个页面不得以“更好看”为由自行改变字号、圆角或边距。

## 功能变更

新增控件必须先有 Feature/Interaction/API/后台/测试映射。效果图中出现但无 Interaction ID 的按钮只能作为禁用示意或必须从图中删除，Codex不得自行赋予功能。
